# Marketplace Opportunity Framework

An agent-ready framework for testing whether a venture idea has marketplace potential, from broad markets down to micro-niches. An agent with a thinking model uses it to analyse, strategise and generate suggestions with evidence, ranges and an independent red team, and to finish with cheap experiments rather than false confidence.

> **Its limit, by design:** desk research can kill bad ideas cheaply and generate well-formed hypotheses. It cannot establish demand, supply willingness or liquidity. The framework is judged on how well it screens and points to the right experiments, not on how confidently it picks winners.

## What it does

1. **Starts from transactions, not "markets".** Every candidate reduces to a transaction card: who pays whom, for what, how often, through which channel, with what friction and liability.
2. **Generates a market tree** from L0 sector to L4 micro-niche. It uses named operators (descend, transform, ascend) under several lenses, to avoid "Uber for X" mode collapse.
3. **Kills before it scores.** Seven gates:
   - G1 marketplace fit
   - G2 leakage
   - G3 atomic network
   - G4 regulation
   - G5 entrenched incumbent
   - G6 economics
   - G7 AI substitution

   `unknown` is never a pass.
4. **Scores paths, not points.** An entry wedge plus an expansion sequence is scored with anchored 1–5 criteria, ranges, evidence coverage and several weight profiles. Rank flips are flagged as values choices.
5. **Builds 2026 realities in.**
   - Profit sits in advertising and fulfilment above the commission line.
   - AI substitution and agent bypass are first-class risks.
   - Regulators deputise platforms on product safety, customs, tax and worker status.
6. **Separates generation from judgement.** An independent critic sees the evidence, not the reasoning.
7. **Ends in validation.** Assumptions are ranked by impact × uncertainty, each with the cheapest test that could falsify it.

## Use it

**Claude Code.** Clone the repo and open it. The skill is exposed at `.claude/skills/marketplace-opportunity`, a symlink. Ask: *"Use the marketplace-opportunity skill to analyse: <idea>"*.

**Claude apps.** Zip `skills/marketplace-opportunity/` and upload it as a skill.

**Any other agent.** Point it at [`AGENTS.md`](AGENTS.md), then [`skills/marketplace-opportunity/SKILL.md`](skills/marketplace-opportunity/SKILL.md).

**Scripts** (Python 3.9+):
```bash
pip install -r requirements.txt
python skills/marketplace-opportunity/scripts/validate_ledger.py examples/illustrative-run/ledger.yaml
python skills/marketplace-opportunity/scripts/score.py examples/illustrative-run/ledger.yaml
python skills/marketplace-opportunity/templates/sizing_model.py
```

The example is **synthetic** and exists to show formats and scripts. Its warnings (low-confidence, single-source evidence) are intentional.

## Structure

```
skills/marketplace-opportunity/   # the runtime skill (self-contained)
  SKILL.md                        # entry point: rules, stage-by-stage load map with token sizes
  framework/                      # 14 small modules: principles, pipeline, transaction card, tree,
                                  # gates, scoring, sizing, deep dive, strategy, red team, validation,
                                  # evidence protocol, failure modes, data sources
  knowledge/                      # theory, practitioner heuristics, historical patterns,
                                  # 2026 context (perishable), failure library
  config/                         # gates, rubric anchors, weight profiles, generation operators (YAML)
  schemas/                        # ledger and evidence JSON Schemas
  templates/                      # brief, ledger, deep dive, memo, Monte Carlo sizing model
  prompts/                        # orchestrator, researcher, modeller, critic, synthesiser
  scripts/                        # validate_ledger.py, score.py
examples/illustrative-run/        # synthetic worked example
docs/
  framework-spec.md               # single-file spec (generated by tools/build_spec.py)
  testing-the-framework.md        # backtests, golden set, consistency, ablations, calibration
  research/                       # the two research reports behind the knowledge pack
```

**Design choices for agent efficiency:**
- small single-purpose files with front matter;
- a load map so each stage pulls about 2–4k tokens rather than the whole framework;
- machine-readable config and schemas;
- deterministic scripts for scoring and sizing, so no arithmetic happens in prose;
- a ledger on disk as the source of truth across long runs.

## Evidence base

The knowledge pack draws on two research reports in `docs/research/`: a history of marketplaces (ancient to digital, with academic, professional and cultural perspectives) and an analysis of marketplaces as of November 2026. Facts in `knowledge/context-2026.md` are perishable. Check `valid_until`.

## Status

**v0.1.** The gates, anchors, weights and operators are a reasoned starting configuration, **not yet calibrated**. See [`docs/testing-the-framework.md`](docs/testing-the-framework.md) for how to test and tune it. Contributions of backtests, golden-set labels and verified failure cases are especially welcome.
